# M1 diagnostic pilot — 2026-11-20

Approved grid: HumanEval/89,94,105,144,39; K2 and K4; passive, active and
complete rendered token-matched irrelevant input; both fixed Qwen models.
Five isolated controls per model bring maximum total to70. This pilot tests
harness viability, extraction, context validity, cap rates, timings and qualified
energy coverage. It does not test a new behavioural hypothesis. All pilot rows
are excluded from main hypothesis tests. No full run starts automatically.

Exact materials published before generation: docs/PROMPTS_M1_PILOT.md.
Companions: next distinct-entry-point tasks from the documented M1 seed rule's
permutation filtered to the original fixed40 roster. Prefixes are nested for
K2/K4. Target first at pilot indices0,2,4, last at1,3: partial3/2 balance,
identical across model and condition; not complete order counterbalancing.
Never use model success/failure to select companions. No reference/test text
enters prompts. Neutral filler is a deterministic token-prefix of notebook
prose, matched to the entire templated passive input; fragments are disclosed.
These routine implementation choices are recorded under the approved pilot grid; individual prompt review is not claimed.

Keep original M1 config: T0, seed1729, num_ctx32768, CPU threads8, no GPU,
keep_alive0, output2048 per requested function, timeout3600 seconds. Active K2
has cap4096 and K4 cap8192; all other responses cap2048. Longer active outputs
and larger budgets are intervention features, not controlled equal workloads.
Input counts are independently computed using the pinned tokenizer/template.
Assert reserved input+output <=32768. Do not infer a token cap hit as giving up.

Isolation reuse requires identical request/task/model-digest. Existing E0 has
T0.2 and existing M3 controls context8192; neither is the proposed context32768
control. Thus10 missing controls are prepared, without rerunning E0 or M3.

Randomize/interleave the70 logical calls with existing scheduler seed1730.
Sequential25-call blocks, stable60s baselines at both ends, existing drift as
flag, existing failures/coverage/disk/freeze stops. Resume only missing keys,
retaining failures. No evaluator during generation. After all70 calls stop,
score in restricted subprocesses using existing EvalPlus oracle. Return
per-function outcomes and separate target success from all-requested-functions
success. If infrastructure fails, retain logs, report and stop; do not tune the
oracle or edit raw answers. Number of calls is a maximum including failures.

Competing pilot outcomes: viable prompt/extraction path versus context-count
mismatch, high cap/truncation, memory/latency or evaluation failures. Such failures
change feasibility and later design, not evidence for the research hypothesis.
Report all scheduled/completed/scored counts by model/condition, means of actual
API timing/tokens, coverage, flags and baseline overhead. No causal interpretation
or significance test from this pilot. Any later changes need a dated amendment.

Inference boundary: diagnostic five tasks, two small quantized models, one CPU
machine and benchmark, one sample per task/condition/model. Full-study grids,
R1 summaries, newR2 distractors, E4 cache verification and eight-hour feasibility
are not established by preparing this pilot. The owner grid-approval receipt, committed materials, reference validation and active sensor preflight gate first generation.
