# Primary-source related-work comparison

Checked 24 November 2026. Focused search, not a systematic review or proof of priority.

|Publication|Question/design|Main contribution|Overlap|Defensible distinction|
|---|---|---|---|---|
|[Lost in the Middle: How Language Models Use Long Contexts](https://aclanthology.org/2024.tacl-1.9/)|Position of relevant evidence in long input contexts; Question answering and key-value retrieval with controlled positions|Shows position-sensitive utilization|We also vary target position|Code tests, semantic competing specifications and local package-energy estimates|
|[LLM Task Interference: An Initial Study on the Impact of Task-Switch in Conversational History](https://aclanthology.org/2024.emnlp-main.811/)|Effect of task switches in conversation history; Conversational task switches across multiple datasets|Documents history-associated task interference|Direct overlap with our static interruptions|Our M2 is constructed, not an independent discovery of task interference|
|[Multi-Task Inference: Can Large Language Models Follow Multiple Instructions at Once?](https://aclanthology.org/2024.acl-long.304/)|Following multiple instructions in one inference; MTI Bench compares bundled and separate instruction execution|Bundling can improve some tasks; degradation is not universal|Direct overlap with M1|Smaller quantized code models, function-level tests and explicit overlap caveats|
|[Do LLMs Recognize Your Preferences? Evaluating Personalized Preference Following in LLMs](https://arxiv.org/abs/2502.09597)|Preference inference, retention and adherence; Explicit/implicit preferences across conversational lengths and intervention methods|Separates preference-following capabilities|Direct overlap with E5 reminders|Our code-only metric floor limits claims; no new preference benchmark claim|
|[LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory](https://arxiv.org/abs/2410.10813)|Long-term conversational memory abilities; Multi-session histories and curated questions; indexing/retrieval/reading designs|A broader framework and benchmark for memory systems|Availability and reading-stage utilization|We use fixed code specifications, not sustained personal conversation histories|
|[Evaluating Large Language Models Trained on Code](https://arxiv.org/abs/2107.03374)|Functional code-generation correctness; HumanEval tasks and execution-based evaluation|Introduces the benchmark|Benchmark source|We do not claim benchmark novelty or contamination independence|
|[Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation](https://arxiv.org/abs/2305.01210)|Insufficient tests in code evaluation; Expanded generated tests and HumanEval+|Detects errors missed by original tests|Our execution oracle uses expanded partitions|We retain reference anomalies and adapter limits|
|[Qwen2.5-Coder Technical Report](https://arxiv.org/abs/2409.12186)|Code-specialized model family; Model training and code benchmarks|Describes the evaluated model family|Two smallest family members|Our runtime is quantized CPU inference, not an upstream model evaluation|
|[Towards Sustainable NLP: Insights from Benchmarking Inference Energy in Large Language Models](https://aclanthology.org/2025.naacl-long.632/)|Inference energy across models, prompts and systems; Energy benchmarking across NLP configurations|Relates inference cost to outputs and runtime|Prompt and inference-cost motivation|Our package-energy ratios are narrow and exploratory|
|[Evaluating the Environmental Impact of using SLMs and Prompt Engineering for Code Generation](https://arxiv.org/abs/2604.02776)|Prompt strategies, code accuracy and environmental cost; Multiple small/open models and HumanEval+/MBPP+ prompting strategies|Direct prior study of code-prompt efficiency|Strong overlap with Prompt-Energy motivation|No first-energy-study or emissions claim; focus is competing specifications|
|[The Instruction Hierarchy: Training LLMs to Prioritize Privileged Instructions](https://arxiv.org/abs/2404.13208)|Conflicting instructions with different privilege levels; Training and evaluating hierarchy adherence|Addresses prioritization and injection robustness|Distinguishing competing instruction sources|Competing descriptions do not form a security benchmark or training intervention|
|[From Local to Global: A Graph RAG Approach to Query-Focused Summarization](https://arxiv.org/abs/2404.16130)|Graph-assisted query-focused summarization; Entity graph indexing and community summaries|A graph RAG design for corpus-level questions|Graph-assisted retrieval motivation|MemoryGraph has a small alias/entity bonus, not this full GraphRAG architecture|
|[Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory](https://arxiv.org/abs/2504.19413)|Scalable persistent agent memory; Memory extraction/update/retrieval and graph extension|An integrated memory-system evaluation|Practical retention/retrieval direction|Our companion prototype lacks an integrated correctness/energy or real-user evaluation|
|[EvalMem: An Operation-Level Diagnostic Framework for Long-Term Memory Systems](https://arxiv.org/abs/2609.22231)|Distinguishing encoding, retrieval and generation defects; Operation-level examiners and oracle-evidence comparisons|Direct prior diagnostic separation of memory-system operations|Strong conceptual overlap|The separation is not novel; our observations concern behavioral specification testing|
|[LongMemEval-V2: Evaluating Long-Term Agent Memory Toward Experienced Colleagues](https://arxiv.org/abs/2605.12493)|Experience-oriented long-term web-agent memory; Curated questions about customized environments|Extends memory evaluation beyond user-history recall|Recent boundary for memory claims|Our static code tasks do not evaluate environment experience or long-term agents|
