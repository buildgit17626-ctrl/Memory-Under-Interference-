Memory Under Interference:
Context Utilization, Speciﬁcation Confusion, and Inference Eﬃciency
in Small Code Language Models
Dhruv Brahmbhatt
IIT Madras student; independent researcher ∗
24 November 2026
Preprint – Version 1.0 – Not peer reviewed
Abstract
Having relevant information in a prompt does not es-
tablish that a model uses it successfully. We study
this distinction through code-generation tests with two
small quantized Qwen2.5-Coder models on one CPU
laptop. Seven completed studies contain 5,528 main-
study logical requests; diagnostic pilots and an incom-
plete cache study are kept separate. We vary addi-
tional task descriptions, semantically competing spec-
iﬁcations, static interruptions, retention policies and
a code-only preference. A posthoc cross-scoring anal-
ysis ﬁnds more alternative-consistent failures under
competing rather than irrelevant context for the 1.5B
model: 8.97 percentage points, task-bootstrap 95% in-
terval [3.21, 16.67], over 39 matched tasks. The corre-
sponding 0.5B estimate is inconclusive, and the 1.5B
ﬁnding weakens under adverse coding of censored out-
comes. Oracle context retention has lower observed
estimated CPU-package energy per correct solution
than full history, but accuracy diﬀerences remain un-
certain and length, position and output changes are
confounded. A registered preference-adherence met-
ric reaches an observed ﬂoor; a separate format audit
shows why it should not be read as a general failure
to retain preferences. We document a companion re-
trieval prototype without claiming an integrated bene-
ﬁt. The contribution is a narrow, auditable behavioral
study, including negative results and measurement lim-
itations, rather than a measurement of internal mem-
ory or cognition.
1 Introduction
Longer prompts make more information available to a
language model, but they also introduce material that
may be irrelevant or incompatible with the current re-
quest. An assistant can have a correct task speciﬁ-
cation in view and still produce code that does not
satisfy it. The practical question is therefore not only
how much context a runtime accepts, but which spec-
iﬁcation the generated program satisﬁes and what the
attempt costs.
Prior work already shows position-sensitive context

lowing user preferences [ 4, 7, 15]. Multi-task infer-
ence can also help some tasks [ 11]; degradation is
not a universal consequence of bundling. We do not
claim to discover these phenomena. Instead, we ex-
amine their manifestations in two small local code
models with execution-based outcomes, carefully qual-

sponses.
Three questions organize the report. First, are ad-
ditional task descriptions associated with diﬀerent tar-
get outcomes from equally long neutral ﬁller? Second,
do computationally competing descriptions increase re-
sponses that pass an alternative speciﬁcation’s tests
while failing the target’s tests? Third, how do retained
context and preference instructions relate to correct-
ness and inference cost? These questions are delib-
erately behavioral. A failing output does not reveal
whether a model recognized a fact, deliberately ignored
it, or reached an internal capacity limit.
The study grew from an earlier Prompt-Energy ex-
periment into several revised designs. Version 1 freezes
completed observations and audits their actual scope.
It contributes paired code-task comparisons, a posthoc
cross-speciﬁcation error analysis, an explicit account of
cost-per-correct uncertainty, and a documented scoring
failure that limits the preference result. The original
broader plan included experiments not completed here;
their absence is reported rather than ﬁlled with pre-
dicted results.

Context and instruction interference. Lost in

smaller code models and diﬀerent tasks do not contra-
dict that result merely because some bundled condi-
tions perform worse. Instruction Hierarchy addresses
conﬂicting privilege levels and training for robust prior-
itization [12]. We neither train a hierarchy nor evaluate

3 Evaluation Framework
We distinguish four operations. Availability means
that the intended speciﬁcation is literally present in
the rendered prompt. Retrieval means selecting stored
material for a prompt; it is only demonstrated in the
separate companion prototype. Utilization is opera-
tionalized by the generated function’s observed test
outcomes. Eﬃciency describes measured tokens, la-
tency and qualiﬁed CPU-package estimates, including
failed attempts. None is a direct measurement of inter-
nal memory capacity.
For a target program test suite T and a correspond-
ing computational alternative A, an uncensored re-
sponse belongs to one of four cells: target-only pass,
alternative-only pass, both pass, or both fail. We call
the second cell alternative-consistent or distractor-only
success. “Speciﬁcation confusion” in the title refers
only to this operational error pattern. Passing a ﬁnite
suite does not prove general program correctness, and
a diﬀerent failure may reﬂect syntax, extraction, policy
restrictions or ordinary algorithmic error.

4 Experimental Methodology
4.1 Data, runtime and actual study
scope
The models are qwen2.5-coder:0.5b and
qwen2.5-coder:1.5b, both Q4_K_M quantiza-
tions, with exact model digests recorded in frozen
jobs. Inference used Ollama on Windows 11, an Intel
i5-13420H CPU and approximately 16 GB RAM, with
eight inference threads and num_gpu=0. Generation
was sequential, with randomized interleaved condition
schedules. Recorded block-start checks observed AC
power and Best performance; these snapshots do not
prove an invariant host state throughout every request.
Decoding settings, templates, native token counts,
raw outputs and retry records are retained.
The main request counts are: isolated strategy com-
parison, 1,968; initial context load plus its isolation
controls, 280; task bundles, 1,040; retention, 400; re-
vised semantic interference plus isolation, 1,040; static
interruptions plus isolation, 400; and preference place-
ment, 400. These sum directly to 5,528. Pilots are
separate observations. The revised cache study saved
76 of 400 planned full requests and is a partial appendix
diagnostic. Repair and recognition/hint studies were
not conducted.
The isolated strategy study covers all 164 Hu-
manEval+ tasks, comparing P1 and P3_1 with
three temperature-0.2 samples per task/model, context
8,192 and output budget 2,048. The strategies diﬀer in
both instructions and an external example, so this is
not a pure example-eﬀect contrast. Initial context load
uses 20 held-out-eligible tasks per model, with fresh
temperature-0 no-ﬁller outcomes; the sample used for
selection is never the isolation comparator. Its model-
selected populations and weaker renamed-speciﬁcation
distractors remain separate from the revised designs.
The later studies use the original ﬁxed 40-task roster
for both models. They use temperature 0 and one gen-
eration per task-condition-model. Context is 32,768

4.2 Controlled context constructions
Passive task load adds other task descriptions; active
load requests their functions as well. K ∈ { 2, 3, 4, 6};
neutral ﬁller matches passive input length. Target
placement and companions are ﬁxed. Active requests
do more output work, so focal-target, per-function
and whole-bundle endpoints are kept distinct. Reused
component-isolation outputs are lookup references, not
newly measured bundle execution.
Revised semantic interference crosses three ﬁller
types, ﬁller-token targets 1,000/2,000 and target be-
ginning/end, with matched isolation controls. Com-
peting descriptions change a computational require-
ment, such as strict versus non-strict comparison or
inclusive versus exclusive boundaries. Alternative ref-
erences and distinguishing inputs were validated. The
model sees descriptions, not the alternative implemen-
tation or hidden tests. Related/irrelevant labels are
authored coarse categories; they are not calibrated se-
mantic similarity. Filler budgets do not guarantee iden-
tical complete input lengths across every wrapper, an
important limit on attributing diﬀerences solely to con-
tent.
Retention compares full history, target/query only,
verbatim target replay, lossless target-format com-
paction, and oracle retention. Eight ﬁxed distractor
descriptions form full history. No-history omits the ex-
plicit code-only preference, while the oracle retains tar-
get, preference and ﬁnal query. Compaction removes
redundant target formatting and drops other history;
it is not semantic summarization of a conversation.
These policies jointly change length, position, repeti-
tion and sometimes instruction content.
Static interruption conditions contain neutral ma-
terial, one similar competing description, one other-
domain description, or three other-domain descrip-
tions. Loaded complete input counts match, with the
same target and ﬁnal instruction. Descriptions and
acknowledgements are literal transcripts, not tasks ex-
ecuted earlier by the model. Similarity, count and
diversity are not fully crossed. Preference placement
compares absent, immediate, buried, replayed and cor-
rected code-only instructions while preserving the tar-
get/query and distractor history.
4.3 Statistics, exclusions and energy
Intervals use 2,000 paired task-bootstrap draws with
seed 1732. Binary pairs use exact discordant-pair Mc-
Nemar tests; task means over repeated cells use exact
paired sign swaps. Holm correction is within speciﬁed
families: two isolated strategy tests, two initial-load
primary tests, two revised-interference primary tests,
six retention tests and six interruption tests. The new
cross-pass audit uses four posthoc tests. These correc-
tions do not control every analysis ever examined in
the project. Intervals are pointwise, not simultaneous
family intervals. Null tests do not establish equivalent
accuracy.
The audit preserves failed requests and capped gen-
erations. Caps are nonpasses for bounded correctness
endpoints but unknown for the uncensored cross-pass
taxonomy. API, input or evaluator-infrastructure fail-
ures are missing for valid-input accuracy and sepa-
rately reduce operational yield. We report cap ex-
clusion, optimistic bounded-correctness scenarios, ad-
verse cross-pass coding, independently labelled eli-
gibility subsets, and exclusion of the documented
HumanEval/32 oracle anomaly. The expanded-test
adapter and sandbox restrictions remain part of the
operational outcome, not an infallible correctness ora-
cle.

5 Contextual Interference
5.1 Context content and additional out-
put work
Figure 2 compares focal-target outcomes under passive,
active and neutral conditions. Passive-minus-ﬁller es-
timates tend to be negative across K in this roster,
but many adjusted comparisons are inconclusive. The
0.5B K = 6 estimate is −25 percentage points, condi-
tional interval [−37.5, −12.5], with Holm p = 0.015625
in its eight-comparison posthoc family. This single con-
ditional contrast does not establish a universal multi-
tasking penalty.
Every bundle-membership graph forms one con-
nected component. Anchor-task bootstrap intervals
condition on the ﬁxed companions and cannot esti-
mate dependence-robust variability from other bun-
dles. Changing K also changes which companion func-
tions appear. Active per-function fractions and whole-
bundle successes are reported against the same compo-
nents’ isolation outcomes in the archive, rather than
equating a passive focal pass with a complete active
bundle. The additional output budget and repeated
component references limit cost comparisons. This de-
pendence limitation is substantive, not a small-sample
footnote to a population-level claim.
5.2 Competing speciﬁcations and
alternative-consistent failures
The revised primary competing-minus-irrelevant
target-correctness diﬀerence is -11.25 percentage
points for 0.5B, interval [-20.62, -2.50], Holm
p = 0 .056396, and -2.50 for 1.5B, interval [-10.00,
4.39], Holm p = 0 .63525. Both comparisons have 40
paired tasks averaged over four length/position cells.
A pointwise interval excluding zero can coexist with
an adjusted test that does not reject; both are re-
ported. Figure 3 shows the cell-level outcomes without
treating them as independent task replications.
Cross-scoring reveals a diﬀerent pattern. For 1.5B,
the posthoc diﬀerence in distractor-only success be-
tween competing and irrelevant contexts is 8.97 per-
centage points, interval [3.21, 16.67], across 39 com-
plete matched tasks; Holm p = 0 .03125. Versus isola-
tion, the estimate is 9.62 points, interval [3.21, 17.95],
in the same four-test family. The 0.5B competing-
minus-irrelevant estimate is 3.12 points, interval [-3.12,
11.25], p = 1. The stronger 1.5B error-type association
therefore does not imply a similarly large change in its
overall target pass rate.
Figure 4 includes every scheduled response, whereas
complete-case inference requires all paired cells. No re-
sponse passes both suites in this dataset. Determinis-
tically selected code examples support the operational
labels: one 0.5B response uses an inclusive compar-
ison where the target is strict; a 1.5B response re-
verses parenthesis-group order as speciﬁed by the alter-
native. Separate authored distinguishing cases agree
with these labels. The examples are an audit sample,
not estimates of a latent reasoning process.
Censoring limits this ﬁnding. Assigning every un-
known competing response against the association and
every unknown control in its favor yields a 1.5B diﬀer-
ence of 6.88 points over all 40 tasks, scenario interval
[−0.02, 15.00], adjusted p = 0 .53125. The favorable
assignment gives 10.62 points, interval [3.75, 18.75].
These are adverse/favorable coding scenarios, not ob-
served repaired outcomes or a formal conﬁdence set
for missingness. The complete-case result is therefore
suggestive but not robust to all cap assignments (Fig-
ure 5).
5.3 Initial context load and static inter-
ruptions
Initial context load shows a near-minus-irrelevant esti-
mate of -27.50 points for 0.5B, interval [-45.00, -10.00],
Holm p = 0.033691, and -2.50 for 1.5B, interval [-17.50,
12.50], p = 1 . These selected populations and weaker
distractors cannot be pooled with the revised semantic
experiment. Nor should the numerically larger initial
eﬀect be taken as evidence of a stronger internal capac-
ity limit.
The six primary interruption comparisons do not es-
tablish a corrected eﬀect. For example, three other-
domain descriptions versus neutral material on 1.5B
give −15 points with interval [−27.5, −2.5], but Holm
p = 0 .421875. This illustrates the distinction between
pointwise intervals and family tests. Its constructed
history and coarse domain labels also preclude a gen-
eral claim about real task switching. Isolated strategy
diﬀerences are similarly uncertain: P3_1 minus P1 is
-2.25 points on 0.5B, interval [-7.77, 2.86], and 2.64 on
1.5B, interval [-1.22, 6.30]. These negative or inconclu-
sive results constrain the narrative.

7 Preference Utilization
The registered adherence predicate requires unfenced
parseable Python deﬁning the target function. It
scores zero out of 400 full-study responses, so both
primary placement/reminder contrasts are at the ob-
served ﬂoor. The instruction asks for code only but
does not explicitly prohibit Markdown fences. Treat-
ing this ﬂoor as evidence that the model forgot every
preference would therefore overstate what the instru-
ment measures.
A separate posthoc audit preserves the original
scores and records fences, outside prose, comments,
docstrings and a fence-tolerant syntax predicate. For
1.5B, each explicit-preference condition has 40/40
fence-tolerant outputs, whereas no-preference has
21/40. For 0.5B, explicit conditions range from
36/40 to 39/40, versus 15/40 without the preference.

Memory Retrieval
The existing MemoryGraph imple-

It stores editable local plain-text memories; TF-IDF

terface’s ranking. These are template-based synthetic
rankings, not held-out code-generation outcomes or es-
timates of real-user behavior. Grouped classiﬁer evalu-
ation splits by ﬁctional proﬁle, but repeated templates
can still supply shortcuts; the random forest’s recorded
perfect synthetic result should not be read as general
memory-understanding ability.
A recorded two-prompt local demonstration supplies
a pytest preference, yet the memory-enabled response
begins with import unittest . Both successful API
responses reach the 128-token output budget, and cor-
rectness and energy were not scored. A preceding failed
demonstration run is retained separately. This is a
concrete example of availability without the intended
surface behavior, not a controlled integrated beneﬁt or
failure-rate estimate. The HumanEval+ study and this
synthetic benchmark are never pooled. An integrated
MG1 comparison remains Version 2 work.

The retention results separate another pair of ques-

10 Limitations
The results concern two small quantized models, one
code benchmark and one CPU laptop. Training-set ex-
posure is unknown; benchmark familiarity is neither
ruled out nor inferred from a pass. Fixed task ros-
ters, noisy eligibility selection, one structural genera-
tion per cell and only three isolated stochastic samples
limit generalization. Shared functions connect M1 bun-
dles and prevent robust component-level intervals. The
smaller-model eﬀects need not predict larger models,
other quantizations, GPUs or cloud deployments.
The study is revised and partly exploratory. Reg-
istrations and dated amendments are preserved, but
the ﬁnal synthesis and cross-speciﬁcation audit are
posthoc. Local Git hashes support provenance, not
independent public timestamping. Family correction
does not erase prior exploration. The separate syn-
thetic prototype benchmark is small and templated,
with no user study.
Scoring depends on ﬁnite test suites, extraction and
a Windows restricted subprocess adapter. These con-
trols are documented rather than described as a com-
plete adversarial sandbox. Alternative construction
and similarity labels are AI-assisted and authored; rep-
resentative witnesses are not exhaustive semantic vali-
dation. Adverse censoring weakens the principal cross-
pass result. No recognition, internal state or inten-
tional giving-up measurement exists.

CPU-package estimates are not calibrated process-

clock/sampling gaps, thermal eﬀects and approximate

calibration or independent block errors. Short requests

11 Conclusion
This independent study provides a limited but in-
spectable record of how small code models behave with
competing context. The 1.5B complete-case outputs
show more alternative-consistent failures under com-
peting speciﬁcations, while adverse cap assignments
weaken that result. Reduced oracle context has lower
observed estimated energy per correct solution, but the
experiment does not establish equivalent or improved
accuracy, identify an internal memory mechanism, or
validate a practical retriever. One clear negative ﬁnd-
ing is that the registered strict preference score reaches
a ﬂoor and cannot carry the intended retention inter-
pretation. Version 1 reports these limits alongside the
eﬀects; Version 2 can evaluate retrieval and generation
together.
