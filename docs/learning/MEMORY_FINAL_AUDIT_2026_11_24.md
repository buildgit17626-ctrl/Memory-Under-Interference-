# Understanding the Memory Under Interference audit

This authorized milestone audits existing observations. It does not resume a
supervisor, ask a model for new answers, replace primary scores, or approve a
scientific conclusion. The owner reviews interpretations before a manuscript.

## What the code does

The offline schedules define intended jobs. Calls identify completed logical
requests, including terminal failures; starts and responses retain individual
retry attempts. Scores point to those calls and separate target functions and
test partitions. Blocks join each request to its idle baselines and HWiNFO
sensor mirror. The audit checks those links before computing comparisons.

`analysis/memory_audit/records.py` normalizes calls and function occurrences.
`provenance.py` compares saved fields against every frozen offline job.
`sensors.py` hashes inputs, verifies recorded CSV prefixes and independently
integrates used power windows. It does not fix or rewrite sensor CSVs.

`effects.py` keeps both arms and every repeated outcome together within a
task. Binary pairs use exact McNemar tests; repeated-cell task means use exact
paired sign swaps. Holm corrections apply within the declared families.
`statistics.py` supplies paired bootstrap intervals and ratios. A pointwise
95% interval is not a multiplicity-adjusted simultaneous confidence interval.

`mechanisms.py` cross-scores saved code against alternative contracts, using
the same restricted subprocess evaluator. It also audits literal R1 prompts,
E5 syntax/format features, and M1 bundle membership. New scores go into an
audit journal; original scores stay unchanged. `examples.py` separately checks
deterministically selected code on authored distinguishing witnesses.

`robustness.py` examines caps, extraction, alternative baseline subtraction,
drift/short-window exclusions and paired cost ratios. `supplement.py` supplies
explicitly posthoc missing control comparisons and joint preference outcomes.
`report.py` and `review.py` generate tables and a skeptical interpretation draft.

## How to read the outputs

Start at `artifacts/memory-audit/2026-11-24-v1/REVIEWER_AUDIT.md`, then inspect
`PHASES_1_4_REPORT.md` and `CONDITION_TABLES.md`. The JSON/CSV tables retain
denominators, task IDs, source keys, uncertainty and missingness. Full evidence
paths are in `calls.csv`; source hashes are in `input-manifest.json`.

A cap is a nonpass for the bounded registered endpoint, not a claim of refusal
or lack of knowledge. Invalid/API/infrastructure observations are missing for
valid-input correctness and separately reduce operational yield. Removing
observations changes the population; it cannot silently improve the primary.

Energy per correct is total covered-attempt energy divided by covered passes,
including failed-attempt energy. It differs from energy of successful attempts.
HWiNFO CPU-package estimates are not wall-plug energy. Bootstrap variation does
not measure physical sensor calibration, unrelated process use, or uncertainty
in the approximate post-load boundary. No energy values are clipped or imputed.

M1 asks for multiple functions in active mode. Its outputs and reused isolated
references overlap across bundles, so function occurrences are not independent
tasks. One connected membership component prevents a robust component CI.
Conditional anchor-task intervals are useful descriptive diagnostics only.

## Five questions the owner should be able to answer

1. Why must E0's three generations be resampled together within a task?
2. How can distractor-only success increase without a large target-accuracy drop?
3. Why does R1's reduced oracle context not evaluate automated retrieval?
4. Why can an all-zero strict adherence score conceal differences in fenced code?
5. What changes when short or drifted energy windows are excluded?

## Assumptions and limits

- The audit can reproduce registered estimands but remains posthoc work.
- Scores measure test-suite outcomes, not internal cognition or recognition.
- Fixed 40-task studies and initial model-selected M3 populations stay separate.
- Held-out eligibility labels are noisy single-generation estimates. E0 sample0
  used for selection is excluded from that sensitivity's comparison outcomes.
- No human semantic adherence annotation or external sensor calibration is claimed.
- No E3, U-family, semantic summarization or MemoryGraph outcome exists here.
- Literature verification, preprint drafting and public data archival are later work.
